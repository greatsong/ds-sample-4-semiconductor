# 6차시 기록 — 빈칸이 절반을 넘는 열 제거·중앙값으로 채우기

## 10101 홍길동
- 오늘 결정한 것: 상수 열을 뺀 뒤 빈칸이 절반을 넘는 열 28개를 뺐다. 빈칸 비율은 50.7%~91.2%였다. 남긴 센서 열은 446개다.
- AI에게 보낸 프롬프트(원문): 상수 열을 뺀 센서 열 가운데 빈칸이 50%를 넘는 열이 몇 개인지, 그 열들의 빈칸 비율이 얼마부터 얼마까지인지 보여 줘.
- AI가 준 것 중 고치거나 버린 것과 그 이유: AI가 기준을 30%로 하자고 했는데 받아들이지 않았다. 30%로 하면 32개가 빠지는데, 우리 이유는 "절반 이상을 채우면 만든 값이 된다"는 것이라 기준을 50%로 정했다.
- 느낀 점: 기준 숫자 하나도 이유가 있어야 발표 때 설명할 수 있을 것 같다.

## 10102 김영희
- 오늘 결정한 것: 남은 빈칸 10,868개는 그 열의 중앙값으로 채우기로 했다. 센서 값에 아주 큰 값이 섞여 있어서 평균보다 중앙값이 덜 흔들린다.
- AI에게 보낸 프롬프트(원문): 남은 빈칸을 각 센서 열의 중앙값으로 채우려고 해. 이때 중앙값은 학습 데이터에서만 계산하고, 시험 데이터의 빈칸도 학습 데이터의 중앙값으로 채워 줘.
- AI가 준 것 중 고치거나 버린 것과 그 이유: AI의 첫 코드는 데이터를 나누기 전에 전체 데이터의 중앙값으로 빈칸을 채웠다. 그러면 시험 데이터의 값이 학습에 섞이므로, 나눈 뒤 학습 데이터에서만 중앙값을 계산하도록 고쳐 달라고 했다.
- 느낀 점: 프롬프트에 분명히 적었는데도 AI가 순서를 바꿔서 코드를 직접 확인해야 했다.

## 10103 이철수
- 오늘 결정한 것: 전처리 판단(상수 열 116개 제거, 빈칸 절반 초과 열 28개 제거, 중앙값으로 채우기)과 이유를 README 데이터 부분에 표로 정리했다.
- AI에게 보낸 프롬프트(원문): 앱의 데이터 보기 탭에 우리가 한 전처리 판단을 표로 보여 줘. 판단, 열 수, 처리 방법 세 칸이고, 열 수는 코드에서 계산한 값이 들어가게 해 줘.
- AI가 준 것 중 고치거나 버린 것과 그 이유: AI가 열 수를 116, 28처럼 숫자로 직접 적어 넣었다. 데이터가 바뀌면 틀린 숫자가 남으니 코드에서 계산한 값을 넣도록 고쳤다.
- 느낀 점: 숫자를 손으로 적으면 나중에 틀려도 모른다는 걸 알았다.
